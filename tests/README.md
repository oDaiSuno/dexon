# 测试套件宪法

> 新增跨组件行为测试与支持层集中于本目录，现有有效测试仍可留在 `src/` 和 `scripts/` 原位运行。
> 迁移按功能域进行（见 `docs/test-spec-inventory.md`）；目录位置不是测试质量的证明。
> 当前存量豁免名单已清空，入口、覆盖去处与验证边界见 `docs/test-rebuild-review.md`。

## 三条判据

每个测试必须同时满足以下三关。机器只能识别第一关中的部分反模式，不能证明任意行为不变重构都不会破坏测试：

| 判据       | 内容                                                                                                                                   | 执法方式                  |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **改名关** | 任何行为不变的重构（改名、换实现、抽函数）后，测试必须仍绿。禁止把自家源码当文本读取后做断言；禁止 stub 自家模块；禁止断言内部调用顺序 | `npm test` 启动时机器拦截 |
| **造句关** | 测试名必须读得成一句行为规格："当 X 发生时，系统应该产生 Y"                                                                            | 评审执行                  |
| **独立关** | 期望值来自 fixture、规格常量或人工算例，绝不自"用同一算法再算一遍"                                                                     | 评审执行                  |

## 边界地图

测试只能站在真实调用者接触系统的地方，包括公开函数和服务接口，不包括专为测试开放的内部出口：

```
S0 公开逻辑接口        —— 实际调用者使用的输入、返回值和订阅结果
S1 用户眼前的界面      —— 真实 DOM 里的 React 组件
S2 进程契约            —— src/contract 声明的 renderer ↔ preload ↔ main ↔ agent-host 通道
S3 操作系统边界        —— 文件系统、窗口、托盘、deep-link、自动更新
S4 网络边界            —— Telegram / Feishu / Weixin 的 HTTP API
S5 子进程边界          —— pi agent 本体、托管进程
```

图里没有"某个内部 hook""某个 service 的私有方法""某个文件有几行"——这些不是缝隙，是墙纸的纹路。

## 分区

```
logic/     纯逻辑行为测试（fixture 驱动，零 mock）
dom/       界面行为测试（真实 DOM 挂载，断言用户可见结果）
contract/  进程契约测试（穿过真实 handler 入口调用）
services/  服务集成测试（真实临时目录、真实子进程）
adapters/  Telegram/Feishu/Weixin 适配（仅允许 mock 网络 API）
e2e/       现实验证（smoke 与真实流程，必须留下可检查的 artifact）
```

## 页面事件、清理与真实布局

- 输入、选择、点击和键盘操作走 `tests/support/dom-events.mjs` 的真实 DOM 事件；不得读取 React 的私有属性后直接调用处理函数。
- `tests/support/renderer.mjs` 的 `mount(t, Component, props, { release })` 为每个场景登记自动清理，同时关闭页面与该场景借用的通信环境。挂载失败、卸载失败和重复关闭都不能污染下一场景；多个释放错误应一起报告。
- 浏览器尺寸与交叉通知通过 `tests/support/browser-observers.mjs` 按 DOM 目标发送。用例看页面结果，不选择某个内部观察器，也不固定显示时必须存在几个计时器或监听器；卸载后没有自有资源遗留仍是有效规格。
- JSDOM 不测布局。导航的展开/收起宽度、长名称截断、横向溢出、真实 Tab 焦点和键盘操作由 `npm run test:nav-layout-electron` 检查；真实聊天卡片的位置、编辑和发送、四档字号、两档宽度及窄屏由 `npm run test:chat-layout-electron` 检查。两者加载生产样式、Tailwind reset 与离线字体，保留真实组件和通信客户端；仅另一进程的回答使用夹具，不复用替换客户端的开发预览。
- 聊天与导航原生检查按可访问角色、名称和正式标签关系找区域与控件，不按内部类名、直接子节点或按钮的父层猜测位置。760/960px 测量的是完整输入面板、消息区域与工具卡，而非内部打字区；224/52px 测量的是命名的主导航，长名称高度测量的是工作区控制区。
- 原生检查共用 `scripts/electron-test-run.mjs`：隔离 HOME、Electron 配置、Agent、会话和临时数据，限制执行时间，核对当前进程的完成记录，再清理临时环境。退出码为零、旧报告或截图存在都不能单独宣告通过；布局检查还必须完成列出的全部场景。
- 导航和聊天的测量及截图分别保存在 `.artifacts/nav-layout-electron/` 与 `.artifacts/chat-layout-electron/`；入口均可通过 `--out <目录>` 指定位置。原生窗口可能短暂显示，生成截图本身不是通过，必须同时核对实际测量与页面行为。

## mock 白名单

只在以下外部边界提供测试回答；自家组件、策略、通信客户端和能正常加载的真实 SDK 保持真实：

| 允许 mock                                   | 理由                                             |
| ------------------------------------------- | ------------------------------------------------ |
| 网络 API（S4）                              | 外部系统                                         |
| 时间与随机性                                | 物理边界                                         |
| 另一个进程的回答（S2 / S5）                 | 保留真实通信协议，不替换自家客户端               |
| 不可经济复现的操作系统 / 浏览器能力（S3）   | 如剪贴板失败、Git 命令暂停、JSDOM 缺失的几何能力 |
| 不可真实化的 Electron shell（对话框、通知） | 平台边界；原生生命周期另由 Electron 验证         |

**自家模块一律禁止 mock。** 需要隔离时，在真正的外部接口提供测试回答，调用它的自家实现仍加载真实代码。文件、进程和网络能在临时环境中真实运行时，优先真实运行。
测试与打包代码之间确需传状态时，用 harness 桥接对象（`globalThis.__xHarness = {...}` 是允许的；
往 `globalThis` 数组里 push 调用记录再断言顺序，是禁止的）。

## 静态约束的流放地

行数预算、色值令牌、导入顺序、i18n 键覆盖这类约束**不是行为**，不属于测试套件：

- 架构约束 → `npm run check:architecture`（`scripts/check-architecture.mjs`），分两级：
  - **不变量（阻断）**：结构契约——必备模块到岗、结构变更必须同步契约。改一个名字就该改一行契约，这是让架构决策显式化。
  - **卫生指标（只报告）**：行数预算。行数是复杂度的间接代理，不是危害本身——好文件可能超长，坏文件可能很短；把它绝对化会诱发为过检查而人为假拆分。超出预算触发审视而非直接失败；`--strict` 可临时强制。
- 安全约束 → `npm run check:desktop-security`（含切片四批迁入的离线资产：零 CDN、KaTeX 本地字体、CSP 字体/样式源）
- 设计令牌 → `npm run check:design`（`scripts/check-design.mjs`：令牌/对比度/字体栈/动效降级/主题启动顺序；不固定 JSX 拼写、样式出现次数或组件层级，外观效果改由设置行为与真实 Chromium 测量覆盖）
- i18n 完整性 → `npm run check:i18n`（切片四批起含词典组合结构：分片接线/键集互斥/合并等值/拆分前基准指纹/关键文案双语与属主消费）
- CI 工作流不变量 → `npm run check:desktop-workflow`（切片四批建立：四目标矩阵、Windows 质量门、更新元数据核对、未签名 Beta 状态、SBOM/声明随包）
- 测试基础设施 → `npm run check:test-infra`（真实 Electron 与 SDK 探针：核对 HOME、Agent、会话及平台配置/日志/临时路径都在一次性环境中，退出后确实可删除；不再读取启动器源码猜测隔离是否生效）

硬约束的准入条件：保护真实边界（依赖方向、信任边界）、检查关系身而非代理指标、不冤枉好人。满足三条的规则（如"业务逻辑不得反向依赖界面组件"）才配阻断；经验性规则只配报告。

## 迁移协议

1. 一次一个功能域（垂直切片），三分类处置每个存量测试：**保留 / 删除（已有行为覆盖）/ 转化（新写行为测试）**；静态约束流放到 check 脚本。
2. 一个文件的存量豁免处置完毕，就把它从 `scripts/test-hygiene-allowlist.mjs` 移除。名单清空只证明已登记项目清账，不等于完整覆盖或验证完成。
3. 守卫每轮会报告"检测不再命中"的豁免条目——那可能是真清账，也可能是检测盲区（readdirSync 扫描、模板字符串拼路径等），必须人工确认后才可移除。
4. 每个切片收尾跑一次该域的真实 E2E，留下可检查的证据。
