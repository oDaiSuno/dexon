# 测试套件重构：从源码镜像到实际结果

> **2026-10-15 后续修复状态：代码已改，尚未重新运行。** 本轮只处理评审中的 1–4 项：
> 保留真实 `/api` 与事件转换、移除私有定位依赖、保证失败后完整释放、统一普通控件操作。
> 5–9 项不在本轮修复范围。本文原有通过记录、截图和文件清单对应修复前的版本，不能作为当前改动的通过证明。
> 本轮没有运行测试、构建、检查器、lint、类型检查或 Electron；仅做源码阅读、差异核对和源码语法解析。
> 技能目录改验“切目录后，旧回复不能覆盖新选择”；不再从伪造 `fetch` 的内部取消信号推断跨进程请求已取消。
> 聊天与导航原生检查中残留的类名、层级定位已继续修改，见第 14 节；这些修改同样尚未运行验收。
> 附件与技能引用测试已进一步移除自写序列化及内部 token 属性依赖，改查页面与实际发送结果，收尾范围见第 15 节；本次也未运行或提交。

## 1. 先看整体：这次改的不是产品层数，而是测试站的位置

先解释几个名字：React 负责界面；`api-client` 是界面发送后台请求的代码；Main 管理原生窗口，Host 管理 Agent 和工具；RPC 是它们交换请求、回复和事件的消息通道；SDK 是实际使用的 Agent 程序库。DOM 指界面真正生成的元素，JSDOM 是 Node 中的浏览器替身，并非真实 Chromium。

应用原本就有两条真实路径：

```text
用户操作 → React 界面 → api-client → RPC 消息 → Host / Main → 文件、进程、浏览器
渠道消息 → 真实 Agent / SDK → 会话、工具 → 模型服务与其他进程
```

旧测试中有两种捷径：直接读取产品文件，检查里面有没有某段文字；或者在打包时把自家组件、客户端、翻译和策略换成简化版本。前一种会因局部改名失败，后一种可能让真实组件之间的接线错误完全不参与测试。

现在分工是：

- **行为测试**使用真实组件、客户端、策略和 SDK，观察界面、公开返回值、事件与真实临时文件。
- **外部回答**放在网络、另一进程、时间及操作系统 / 浏览器能力的边界。不是把调用边界的自家模块替换掉。
- **静态检查**负责依赖方向、设计规则、词典、离线资产、安全和工作流。这些规则有价值，但不冒充运行行为。
- **现实验证**由真实 Electron、浏览器与托管进程流程负责。JSDOM 不能证明原生窗口、渲染进程和系统进程树正确。

本次接着已有六批迁移继续实施，保留其成果；不是重新设计整个产品。有效旧测试也不为搬目录而搬目录。`src/`、`scripts/`、`tests/` 三处统一运行。

## 2. 运行入口：先确保测试真的运行

### 原来

运行器只发现 `src/**/*.test.mjs`。即便 `tests/` 和 `scripts/` 的测试写得正确，默认命令也可能不执行它们。

### 现在

`scripts/test-runner.mjs` 将三个目录都传给 Node，默认并发 3，可通过 `PI_TEST_CONCURRENCY` 调整。`PI_TEST_TIMEOUT_MS` 保留单测试超时控制。错误配置直接拒绝，不默默回退。

`tests/contract/test-entry.test.mjs` 在临时目录的三个位置各写一个真实子测试，让它们独立写出结果文件，再检查三个结果是否都存在。它不只检查运行器拼出了什么参数。

递归模式必须作为一个参数传给 Node：手动运行时要写成 `"src/**/*.test.mjs"`，不要让 shell 提前展开。嵌套测试进程不能继承 Node 的 `NODE_TEST_CONTEXT` 标记；测试入口验证暂时移除它，并在结束后恢复。

### 不改的后果

会得到“默认命令全绿”，但新测试从未运行。纳入 scripts 后实际暴露的两个失败，说明扩大入口不能用删掉目录来换取全绿。

## 3. 真实界面与通信：回答放在哪里，谁读取，怎样使用

### 原来

多份打包插件拦截 `@/lib/api-client` 或其他自家模块，再提供测试版本。界面读到的是这个版本，真实客户端的连接、序列化、错误和订阅代码没有参与。

### 现在

```text
测试给出 Host / Main 的回答
  ↓ tests/support/api-host.mjs：旧 fixture 方法对应到真实协议方法
  ↓ tests/support/host-bridge.mjs：真实 createRpcServer + 消息端口
  ↓ 真实 api-client 接收 RPC 回复
  ↓ 真实组件更新
  ↓ 测试检查 DOM、地址或公开回调结果
```

- `tests/support/renderer.mjs` 在 React DOM 导入前安装浏览器环境，提供挂载、更新、点击、输入和卸载；`loadRenderer` 加载真实产品图。
- `tests/support/renderer-api.mjs` 从被测组件的同一个 bundle 安装生产 `installApiShims`；旧 `/api` 请求和 EventSource 先经过真实转换与 RPC，测试仅提供 Host 回复。`deferred-host.mjs` 延迟的是 Host 数据或错误，不再伪造浏览器 Response。
- 普通控件统一由 `dom-events.mjs` 检查是否存在、已挂载、隐藏或禁用后操作；事件使用控件所属的窗口，导入事件 helper 不再另装一个浏览器。document 外部事件、编辑器选区/输入法和故意向隐藏控件注入事件的负例保留专用操作。
- 页面和 Hook 的清理将卸载、Host 关闭、环境恢复纳入同一收尾链；`cleanup.mjs` 逐项释放并汇总错误，不能依赖多个 after 在前一个失败后仍执行。
- `tests/support/host-bridge.mjs` 用 `structuredClone` 传输消息，保留错误的 `code` / `detail`，模拟的是另一个进程的回答。
- `tests/support/api-host.mjs` 将 fixture 中的 `getSession`、`listModels` 等方法接到真实 RPC 方法，安装和关闭时重置真实客户端。
- `src/renderer/components/renderer-real-graph.mjs` 处理路径、图片、样式和包的加载差异。图标及语法高亮仍是真包，不是返回空组件。

本轮定位改为可读文字、角色、控件标签和无障碍引用关系。聊天区域与缩略图补充中英文名称，附件/技能删除按钮使用已有文案作为无障碍名称；这些是用户可读取的界面语义，不是新增测试专用标记。
ProcessFlow 现在检查展开后的文字/工具输入、顺序和“进行中”状态；不再把“找不到某个内部类名”当作证明没有可见箭头，也不声称 JSDOM 证明了装饰图形和动画外观。

JSDOM 缺少 `scrollIntoView`、观察器和 SVG 长度等能力，因此支持层提供平台替身。这些测试不声称证明滚动布局、SVG 路径长度或原生动画；相应原生流程另由 Electron 验证。

## 5. 新测试找到的产品缺陷：错误恢复与显示文字混在了一起

文件：`src/renderer/components/browser/BrowserDock.tsx`。

原代码先把错误翻译成人能读懂的文字，再根据编号决定是否刷新：

```ts
const message = messageOf(cause);
if (message.includes("TAB_NOT_FOUND")) {
  void refresh();
  return;
}
setError(message);
```

翻译后的文字可能不含 `TAB_NOT_FOUND`，因此删除 tab 后恢复不会发生。旧源码断言只看“有编号检查语句”，抓不到这个问题。

现在先检查原始协议错误，只有显示时才翻译：

```ts
const message = cause instanceof Error ? cause.message : String(cause);
if (message.includes("TAB_NOT_FOUND")) {
  void refresh();
  return;
}
setError(messageOf(cause));
```

新的 DOM 测试由 Main 删除 tab，再检查真实 Dock 是否刷新并展示新 tab。先复现失败，再修产品代码。可复用原则：**给机器做恢复判断的信息，与给人看的文字，不应混用。**

## 6. 人工复核补获：不再从测试专用窗口窥探内部

三个例子原本不读取源码、也不替换模块，因此机器零命中仍会漏掉它们：

```js
assert.equal(MessageView.$$typeof, Symbol.for("react.memo"));
getMarkdownComponentIdentityForTest();
store.keysForTest(); // 以及 sizeForTest
```

- MessageView / MarkdownBody 改由 `tests/dom/message-reading.test.mjs` 观察实际文字选择：新内容到来时，已选中的代码、链接、表格及历史消息文字不丢失。
- 删除 MarkdownBody 的测试专用组件映射出口，删除旧 identity 测试，去掉 memo 标记断言。
- ThinkingExpansionStore / Registry 只通过 `getSnapshot`、`toggle`、`subscribe`、`get`、`delete` 观察结果：新块采用最新选择；已观察块不被默认值覆盖；淘汰 / 删除后重新打开折叠；取消订阅后不再通知。删除内部大小 / 键列表出口。
- 一并移除无人使用的 attachment preview 测试专用清缓存出口。正常预览行为未改。
- ProcessFlow 和 assistant usage 的七条测试迁到真实 DOM，点击通过浏览器事件，不再直接调用 React 树上的事件函数。Worktree 的内部组件类型断言改为观察项目切换后移除操作不可见。

反例实验保存了两类证据：将 Markdown 自定义组件改为每次重新挂载，四条文字选择测试因为选区变空失败；只移除 MessageView 的 memo 包装，同样五条行为测试全部通过。禁用 store 淘汰时，新测试因旧折叠选择被错误保留失败。实验均恢复，不留下产品突变。

这些测试证明的是选择与状态保持，**不证明渲染次数或耗时**。性能若要成为阻断规则，应另有可独立说明的性能指标，而不是用框架标记代替它。

## 7. 守卫怎样变强，以及它仍做不到什么

`scripts/test-hygiene-rules.mjs` 使用语法树，而不是把文件中所有字符串都当成执行代码。守卫还跟随测试相对导入的 `.mjs` 辅助文件：

- 命名空间没有 `stub` 字样的自家虚拟替换也拦截；不能把替换藏进 helper。
- 新增测试专用 getter 和组件实现标记规则。
- 守卫测试中的代码示例字符串是数据，不应误报为真实替换。
- 修正真实包路径、外部网络回答和 Electron 平台替身不算自家模块替换。

名单现为空，但它只证明已登记条目清账。动态路径、别名转发、动态构建插件、复杂读取、内部对象窥探、期望值来源和任意重构稳健性，仍需要人工审查。规则的名字、零命中和测试总数都不能证明普遍合规。

## 8. 全套入口与现实验证暴露的三个问题

**npm 环境污染测试前提**：旧测试调用 `npmInvocation("win32", undefined)`，期待 `npm.cmd`。但 `undefined` 会启用默认参数，读取当前 npm 的 `npm_execpath`。直接跑 Node 与经 npm 跑的环境不同。现在明确传 `null` 表示没有继承的 CLI 路径，保留回退启动器期望；产品启动器未改，也没有弱化断言。

**失败后的异步清理**：ChatWindow 测试在 session 请求尚未返回时提前失败。关闭真实 RPC 会拒绝未完成请求；消费者收尾还要使用 React DOM，但旧 teardown 已移除了 `window`。现在先卸载界面，关闭通信，再等清理继续执行，最后恢复借用的浏览器全局。真实故障注入 worker 从失败变为通过，没有删掉这条恢复验证。

可复用原则：**关闭资源不总等于资源的消费者已经收尾。** 测试中的环境恢复也属于资源生命周期。

**Electron 冒烟的假绿**：第一次统一验证退出码为 0，但日志只有“启动第二实例”，没有交接完成。实际原因是冒烟先销毁最后一个窗口，Electron 默认退出，后续检查没有执行；启动器只看退出码，错把提前退出当成功。

现在：

1. `src/smoke/main.ts` 明确由 `finish` 决定测试进程结束，关闭窗口不自动宣告成功；只在完整检查成功后写 `smoke-result.json`，记录完成状态和自己的 pid。
2. `src/smoke/host-checks.ts` 在窗口仍存在时检查第二实例交接、第二实例退出、首窗口显示及首实例继续服务，然后才释放窗口。
3. `scripts/smoke-electron.mjs` 在删除临时目录前读取记录，通过 `src/smoke/result.ts` 校验正常退出、明确完成且记录属于本次启动的进程。缺记录、记录失败或错误进程均不能全绿。
4. `scripts/smoke-result.test.mjs` 四条公开结果协议测试保护这一规则；先逐条 Red / Green。真实 `npm run smoke` 也先因未完成而退出 1，生命周期修复后才留下交接与完整检查成功证据。

这次失败不能靠新增源码顺序正则修复。可复用原则：**退出码 0 只表示进程正常结束，不自动证明检查已经跑完。**
